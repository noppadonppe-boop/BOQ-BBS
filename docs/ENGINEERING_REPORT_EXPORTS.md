# Engineering comparison reports — v0.59

After opening a preparation file and choosing **เทียบค่าจากไฟล์**, use **Excel รายงานเทียบ**, **PDF รายงานเทียบ** or **ดาวน์โหลดรายงานเทียบ JSON**. All three formats use one captured result with the same creation time, source-check time, input digest and report digest. Exporting does not rerun the engine, reread the source document, write project history, approve engineering or unlock Issued. Recompare when current input/Spec/reference changes.

Excel has two sheets: **Comparison** shows captured expectations, actual values, user-entered bounds and captured decisions; **Captured Input** contains source identity/Spec/member context, transcribed source rows, bar inputs and complete report JSON in numbered chunks. Numbers and dates are typed. Missing values stay blank, distinct from explicit zero. Delta formulas recalculate from edited cells, but captured decisions/digests remain tied to the original capture. Editing Excel does not establish a new engineering/source result or approval.

Excel print areas are A3 landscape and fit one page wide, with vertical pagination available. Full machine JSON chunks remain in the workbook but are outside the readable print area. Unicode surrogate pairs are preserved at chunk boundaries. Native Excel16.0 recalculation and printing are verified for the four datasets in this iteration; other datasets, physical printers and production compatibility are not inferred.

The app PDF is an A4 landscape diagnostic report, separate from owner BBS A3/A1 drawings. It presents numerical comparisons, captured source/input identity, all expected/actual/context diagnostics, optional source table/basis and actual bar inputs. Every page has coherent numbering and a review-only/construction restriction. The complete capture JSON is embedded as `engineering-preview.json`; it is byte-identical to the JSON download. No original drawing bytes are embedded. Some PDF viewers do not expose attachments in their UI; the separate JSON download remains available. The implementation uses [PDF-LIB's documented attachment API](https://pdf-lib.js.org/docs/api/classes/pdfdocument#attach).

Source bytes were verified at the recorded source-check time. File checksums bind captured content, not engineering validity or the identity of an approving engineer. A saved result clears when live input/Spec/reference changes. A change or account switch during asynchronous file generation suppresses the late download. Assigned Viewer may compare permitted source bytes and download all report formats, without editing member inputs or continuing a preparation form.
