# ย้ายชื่อ Zone และชั้นทั้งโครงการ

ในทะเบียนสมาชิก กด “ย้ายชื่อ Zone / ชั้นทั้งโครงการ” เลือก Zone หรือชั้น ชื่อเดิม ชื่อใหม่ และเหตุผล ระบบแสดงสมาชิก ตำแหน่ง จำนวนองค์ประกอบ และปริมาณของตำแหน่งที่จะย้ายก่อนเริ่ม ตัวกรองประเภท สมาชิก สถานะ และข้อความค้นหาในทะเบียนไม่จำกัดชุดนี้ การย้ายใช้ชื่อเดิมที่ตรงกันทุกประเภททั้งโครงการ

ชื่อเดิมเทียบตรงตามตัวอักษร รวมตัวพิมพ์ใหญ่/เล็กและข้อมูลไม่ระบุ เลือก “ไม่ระบุ” เพื่อกำหนดชื่อให้ตำแหน่งที่ยังไม่จัดพื้นที่ หรือปล่อยชื่อใหม่ว่างเพื่อล้างการจัดพื้นที่ ชื่อปลายทางต้องยาวไม่เกิน 80 ตัวอักษรและไม่มีช่องว่างต้น/ท้าย หากชื่อปลายทางมีอยู่ ระบบแสดงคำอธิบายว่ารายการจะจัดกลุ่มภายใต้ชื่อเดียวกัน แต่ไม่รวม occurrence หรือลบรหัสตำแหน่ง จำนวนทุกแถวคงเดิม

สมาชิกที่ได้รับผลกลับเป็น Draft พร้อม input epoch ใหม่ การยืนยัน placement และคำยืนยันขอบเขตไม่มีเหล็กเดิมต้องตรวจใหม่ มิติทางเรขาคณิต รูปเหล็ก จำนวนต่อ Mark และการยืนยันมิติที่ไม่ขึ้นกับตำแหน่งคงเดิม Spec และการรับรอง Spec เดิมไม่ถูกแก้ การรับรองสมาชิก/Code99 ที่ผูกรุ่นต้องตรวจใหม่ Frozen และไฟล์ที่สร้างแล้วคงข้อมูลเดิม

ระบบอ่านสมาชิกครบทุกหน้าและใช้รุ่นโครงการที่เปิดตัวอย่างก่อนเริ่ม จากนั้นบันทึก before/after ใน manifest พร้อมเหตุผลและผู้เริ่มงาน ใช้เส้นทาง project change เดิมใน specChangeJobs/spec-manifests โดยไม่เพิ่ม backend หรือแก้ Rules รองรับขอบเขตเดิมสูงสุด 5,000 สมาชิกและ manifest 40 MiB แบ่งเขียนไม่เกิน 25 สมาชิก/4 MiB ต่อครั้ง ล็อกการอ่านรายการ/เขียนข้อมูลทำงานระหว่าง Applying หรือ RollingBack เพื่อไม่แสดงยอดจากงานที่เสร็จบางส่วน สต็อกที่จองอยู่หรืองานส่งออกที่กำลังสร้างปิดการเริ่มชุดนี้

ปุ่มเริ่มย้ายทำงานต่อจนเสร็จโดยอัตโนมัติ หากการเชื่อมต่อหยุดหรือปิดหน้า ให้เปิดโครงการแล้วกดทำต่อการย้ายพื้นที่ หรือยกเลิกและคืนตำแหน่งเดิมจากแถบความคืบหน้า การคืนใช้ before ของเฉพาะสมาชิกที่เขียนแล้วแบบตรงข้อมูลเดิม และไม่เผยแพร่รุ่นโครงการใหม่ การคืนได้ก่อนชุด Complete เท่านั้น เมื่องานเสร็จ หากต้องย้ายชื่อกลับให้เริ่มชุดใหม่พร้อมตรวจสมาชิก Draft ใหม่

ถ้าคำตอบของคำสั่งยังไม่มาภายใน 20 วินาที ระบบตรวจสถานะ job จาก Firebase อีกช่องทางหนึ่งด้วย ID token ของบัญชีเดิม โดยอ่านอย่างเดียวและใช้ Security Rules เดิม ไม่ใช้ service account หรือ backend ใหม่ หากยืนยันว่าบันทึกก้าวหน้าหรือจบแล้ว จึงทำต่อจากสถานะจริง หากสถานะยังไม่เปลี่ยนจะรอคำขอเดิม ไม่ส่งคำสั่งนั้นซ้ำ บัญชีเปลี่ยนหรือถูกปฏิเสธสิทธิ์จะหยุดรับผล หลังแต่ละชุดอ่านสถานะโครงการกลับและไม่ให้ listener รุ่นเก่าทับสถานะที่ตรวจแล้ว หลักการสิทธิ์ของช่องทางอ่านนี้อ้างอิง [Firebase REST API](https://firebase.google.com/docs/firestore/use-rest-api)

หากการอ่านหน้าหนึ่งทาง SDK ยังไม่ตอบภายใน 10 วินาที ระบบเริ่มอ่านรายการทั้งชุดใหม่จากหน้าแรกผ่านช่องทางอ่านกลับ โดยไม่ผสมหน้าจากสองช่องทาง รับ page token จาก Firebase และตรวจชื่อเอกสารให้อยู่ในโครงการ/collection ที่ขอ เมื่ออ่านครบจะยืนยันรุ่นโครงการจากเซิร์ฟเวอร์อีกครั้งก่อนเผยแพร่ยอด การสลับบัญชี/โครงการหรือสิทธิ์ที่ถูกปฏิเสธไม่ทำให้ข้อมูลเดิมถูกเผยแพร่ข้ามโครงการ การอ่านกลับเป็นทางสำรองของคำขอที่รออยู่ ไม่ใช่หลักฐานว่าข้อมูลพร้อมหากยังอ่านไม่ครบ

การทำต่อและการคืนชุด project change ใช้ Firebase document API transaction แยกจากคิว SDK เพื่อให้คำขอที่บันทึกแล้วแต่ยังไม่มีคำตอบไม่กั้นชุดถัดไป อ่านบัญชี โครงการ operation งาน และสมาชิกก่อนเขียน พร้อมตรวจสิทธิ์/ก่อน–หลังตามขั้นตอนเดิม การเขียนสมาชิก สถานะงาน โครงการและ operation อยู่ใน commit เดียว ใช้ ID token เดิมและ Security Rules เดิม ตรวจ UID อีกครั้งก่อน commit และจำกัดเอกสารให้อยู่ในโครงการนั้น รหัสคำขอ/digest เดิมทำให้ retry อ่านผลเดิมได้โดยไม่เขียนซ้ำ หากตอบ commit ขาดหาย ตรวจสถานะที่บันทึกไว้ก่อนแสดงข้อผิดพลาด ข้อมูลสมาชิกอ่านด้วย batchGet เดียวและจัดกลับตามชื่อเอกสาร เพราะลำดับคำตอบไม่ใช่ลำดับคำขอ API อ้างอิง [beginTransaction](https://docs.cloud.google.com/firestore/docs/reference/rest/v1/projects.databases.documents/beginTransaction), [batchGet](https://docs.cloud.google.com/firestore/docs/reference/rest/v1/projects.databases.documents/batchGet) และ [commit](https://docs.cloud.google.com/firestore/docs/reference/rest/v1/projects.databases.documents/commit)

เมื่อทำอัตโนมัติครบ ตัวกรองชื่อเดิมที่เปิดไว้จะตามชื่อใหม่ ส่วนการทำต่อหลัง reload ใช้ตัวเลือกทะเบียนที่เปิดใหม่ หากชื่อที่เลือกหมดไปจากข้อมูล ตัวกรองนั้นจะถูกล้างเพื่อไม่แสดงรายการว่างโดยไม่บอกเหตุ งานและเหตุผลอยู่ในประวัติย้าย Zone/ชั้นในทะเบียน และแยกจากประวัติ General Spec/รับแบบ

Backup เก็บ manifest และงานทั้ง Complete/Cancelled เป็นประวัติพร้อม checksum Restore เก็บประวัติอ้างอิง และไม่เปิดล็อกหรือทำงานชุดเดิมในโครงการใหม่ การทดสอบเฉพาะรุ่นและขอบเขตดูได้ใน [รายงาน](../output/area-change-verification/DEVELOPMENT_REPORT.html) นี่เป็นการจัดตำแหน่งของข้อมูลที่ผู้ใช้กรอก ไม่ใช่การรับรองวิศวกรรมหรือเปิด Issued/Production
