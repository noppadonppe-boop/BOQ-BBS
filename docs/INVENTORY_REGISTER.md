# Inventory register and recorded-balance audit — v0.49

Open a permitted project and choose **ตัดเหล็ก & สต็อก**. The register reads that project's stock, ledger and cutting plans in full server pages. It rejects a read when project version, stock epoch, active view or signed-in user changes. Loading/error states remain visible instead of presenting a partial list as a complete balance.

Filter Standard/Offcut, diameter, grade, location (including an unspecified location) and lot/source/plan text. The displayed table has25 rows per page; selected totals and exports include every matching lot. Cards show on-hand/reserved/available pieces, available length, reusable offcut pieces/length and nominal available mass. Nominal mass uses captured length × circular area × project density; it is not a measured stock weight.

Click the recorded-balance status for a lot to inspect receipts, reservations, cancellation/consumption references and captured before/after quantities. New client stock events use recordVersion2. Old records do not receive invented before/after values, and unknown expected quantity stays blank. Receipt/reservation/consumption origins, duplicate or missing references, plan requirements and complete version2 receipt chains are checked. A matched recorded balance still needs a physical stock count and release acceptance.

Whole-project review counts remain visible even when filters return zero lots. A filtered Excel contains the selected Stock Register and Stock History plus an Inventory Audit of all project lots. A filtered PDF includes an appendix of all recorded project problems. The audit is read-only and offers no balance adjustment command. Correct missing histories through the responsible, authorized data process; a green status must not be used to conceal unexplained stock changes.

If stock/project inputs change, **โหลดทะเบียนล่าสุด** reloads the coherent register. Old previews cannot be exported. Excel/PDF creates a persisted inventory snapshot with its scope, capture time, project version, stock epoch and checksum, then uses the existing export-job/storage/history flow. Inventory snapshots cannot be exported as BOQ/BBS or included as an owner drawing release. Assigned Viewers may read and create their own reports, but cannot receive, reserve or cancel stock. Job ownership checks remain in place.

Excel has three sheets, raw dimensions/quantities, typed dates and visible available-length/mass formulas. It uses A3 landscape print setup, repeated headers and separately configured wide history pages. The app PDF is A3 landscape. Native Microsoft Excel printing has not been accepted; read-only imported/recalculated previews do not establish native print layout.

Backup/Restore preserves immutable histories and actual exported files. Restored working stock resets reservation to0/version1; non-consumed plans become Cancelled and imported events retain their origin. Imported version2 events are historical evidence, so their old stock-version chain is not treated as the newly restored working version. Engineering/placement approval remains reset by the existing Restore policy.
