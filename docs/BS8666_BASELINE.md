## Implemented subset and source map

V3 oblique source pages were inspected from the actual supplied PDF pixels: Table1 physical pages10/11/12, printed6/7/8. Code15 uses A+(C);25 A+B+(E);26 A+B+(C);46 A+2B+C+(E). End dimensions are respectively A/C, A/B, A/C, A/E and use the existing Table3 adapter. For25, if E is critical the source calls for99 with A or B free. Note1 warns to consider fully dimensioned99 as the angle approaches90°. The template accepts a conservative unique-height branch, not all near90° geometry.

For outside diameter do, half-width h=do/2, actual virtual centerline leg lengths li and deflection angle theta, oblique leg extension is h*tan(theta/2). V3 derives each outside scheduling leg from its adjacent extensions; height includes actual square-end projections. Inverse height uses `height = Loutside*sin(theta) + do*cos(theta)` and accepts only `do < height < Loutside`; ambiguous near-vertical template dimensions reject before changing the bar. Code25 requires its curvature pattern;26 parallel end legs;46 equal inclined legs/turns and correct curvature. Explicit coordinates can be reviewed separately; a shape label alone cannot qualify a path.

Exact centerline length is `sum(li) + sum(Rc*(theta - 2*tan(theta/2)))`, angles in radians and Rc the actual entered centerline radius. Note1 comparison records both the Table1 approximate sum and exact tangent/arc sum. If any turn exceeds45°, the entire exact sum controls the cut before rounding upward by the stored increment. At or below45°, the Table1 approximation controls. Nominal d controls mass; supplied outside diameter controls the envelope and inside radius. No automatic tolerance/free-leg adjustment occurs.

V3 software examples (nominal/outside16mm, inner r32mm):15 A400/B290/C605 gives approximate1005, exact996.895, cut1025;25 A300/B400/C150/D200/E505 gives approximate1205, exact1196.494, cut1225;26 A300/B500/C600/D250 gives approximate1400, exact1391.167, cut1400;46 A300/B400/C500/D250/E600 gives approximate2200, exact2175.437, cut2200. Above45° examples15 B350 and26 D400 select exact992.009/1379.459 and cuts1000/1400. These are synthetic transcription/geometry checks, not independent engineering-approved fabrication cases. Old V2 keeps its original centerline fallback for these paths, including the first two cuts1000/1200.

Actual outside drawings show A–E/inside-radius leaders, both B dimensions for46 and Note1 comparison. The A4 check appendix and conditional Excel `BS Note 1` sheet retain selected basis/source version. Final A3/A1/A4 PDFs8/7/7pages were all rendered/visually inspected. Evidence: output/oblique-shape-verification/DEVELOPMENT_REPORT.html. Remaining Table1 formulas13/33/51/67/77, complete99 fabrication/tolerance mapping, ACI and engineering commissioning remain pending.

The app field **R is centerline radius**. The adapter derives **r/R inside radius = centerline radius − supplied outside diameter / 2**. The diameter used in the Table 1 equation and mass remains nominal d. Users must confirm the outside/rib diameter and the derived dimensions against their drawings. If the outside diameter is supplied, placement/cover geometry also uses that outside envelope. For code 11 the scheduling radius must match Table 3; a specified larger radius is handled with code 12 and the corresponding minimum leg checks. No mandrel or bend is silently approved or placed automatically.

Outside dimensions are derived from virtual centerline geometry: code 11/12 A is the second leg plus outside diameter/2 and B is the first leg plus outside diameter/2; code 21 A/C are end legs plus outside diameter/2 and B is the middle leg plus outside diameter. Parentheses show the standard free variable. This applies only to verified shape topology. Separate user-entered A–Z **reference dimensions** are stored as references and do not replace these derived dimensions or control the cut equation.

For v2 codes 31/41/44, A through D/E follow the leg order in Table 1 p.7. End legs add outside diameter/2; internal legs add outside diameter. The template tool performs this inverse mapping, creates a local planar X/Z path distributed in Y, validates the concrete/cover/selected-solid fit and all implemented minimum checks before changing the edited bar. It never confirms placement or dimensions automatically and clears a manual cut override. Existing reference dimensions are retained as comparison data only. Invalid inputs leave the bar unchanged. The template does not infer orientation or reinforcement from a drawing; users check the generated placement and apply/save it explicitly. Same-level crossing inward tails are rejected; these adapters intentionally accept a conservative topology subset. Full self-contact/separation detailing remains pending.

Software example for version preservation: d=16, outside=16, A=260/B=360/C=820/D=310, inner r=70 (centerline 78), code31: v2 formula 1597 -> cut 1600; exact geometric length 1601.566 -> v1 fallback cut 1625. Frozen v1 retains 1625 after explicit project upgrade to v2. Neither is an engineering-approved project detail.

Both exact tangent/arc centerline length and the Table 1 result are retained and labeled. They can differ; BOQ uses the selected cut basis. Synthetic code 21 example: outside A=260, B=520, C=260, nominal d=16, inside r=32 → Table 1 length 976 → cut 1,000 mm. The exact centerline is approximately 973.664 mm → it would round to 975 under a purely geometric method. This is a software fixture transcribed from the supplied equation, not an independently approved project detail. Rounding and fabrication tolerances must also be accommodated in detailing; the app does not automatically move a free leg to absorb them.

Draft data may be saved with visible minimum-check problems so that incomplete detailing can be corrected. Server review to Checked/ApprovedForIssue additionally requires all implemented minimum checks to pass and placements to be confirmed. Manual cut overrides remain pending engineering review. Unknown/unsupported formulas do not silently become BS formulas; a centerline fallback is explicitly labeled. Frozen Draft export remains possible with NOT FOR CONSTRUCTION.

## v0.10 planar Code99 drawing subset
The supplied Table1 printed p.8 and clause8.5 printed p.10 require two surface lines, dimensions from projected outside-surface intersections and an indicated free dimension. `general-v4` provides an explicit Draft subset: planar paths ≤12 nonzero legs, deflection≤90°, circular fillets using the entered centerline radius, and projected outside intersection extensions `outsideDiameter/2 × tan(deflection/2)` at each adjacent bend. L01…L12 identify these general leg measurements and are not falsely mapped to a standard A–E shape formula. All bends, actual inner radius, straight tangent lengths and virtual-point coordinates are repeated in tables. One existing leg can be selected as the free dimension; parentheses indicate selection but no tolerance/cut-rounding adjustment is performed. Other reference A–Z values remain independent.

Figure4 acute constructions and clause8.8 multi-plane fabrication drawings are explicitly not implemented by this adapter. Sampled planar crossings/touches are conservatively refused, but this does not certify separation or manufacturing feasibility. Code99 numerical centerline basis/rounding is unchanged and the server's minimum-review blocker remains. A diagram and explicit free dimension do not establish full clause8.5/Table4 or engineering acceptance. See output/general-verification/DEVELOPMENT_REPORT.html for synthetic evidence.

## v0.11 Figure4 drawing subset

Visually inspected printed p10/physical PDF p14. The Figure4 A and C reference separate support tangents, each perpendicular to the corresponding leg. The shared-vertical-tangent construction is not used for A. For a single bend with deflection theta, centerline radius Rc, outside diameter do, virtual leg lengths l1/l2: trim=Rc*tan(theta/2), outside-circle radius Ro=Rc+do/2, C=l1-trim+Ro and A=l2-trim+Ro. These are geometric drawing spans, **not a BS cut-length formula**. B is the actual envelope projection normal to the incoming leg, including caps/arc extrema. The Figure4 R callout is inside radius Rc-do/2. The numerical engine retains its existing analytic centerline length and rounding; it does not reshape the selected free leg to absorb rounding/tolerances. Source hash/edition unchanged. Supports only one acute internal angle with two legs; full Code99, Table4 tolerance, clauses7.2–7.6, material/end preparation and engineering acceptance remain pending.


## v0.12 isometric coordinate subset

Supplied clause 8.8, printed p10/physical p14, was visually inspected. Optional `spatial-v6` produces equal-axis isometric views for Code99 paths of 1–12 nonzero legs with valid circular bends and deflection up to 90 degrees. It selects one of four isometric viewing octants to avoid looking along a curve or collapsing distinct vertices. The drawing states `Isometric view` on the schedule/detail, includes member XYZ virtual intersections, actual centerline incoming/outgoing tangent coordinates, arc centers and oriented unit normals. Non-right angles are supplemented by coordinates as required by clause8.6. Circular surface silhouette generators and square-end cap projections use the supplied outside diameter; no rear-edge occlusion, rib geometry or collision certification is claimed.

Lxx in this format are explicitly **virtual centerline leg lengths**, with separate tangent straight lengths and bend trims. They are NOT BS outside bending dimensions. The stored free-leg selection is shown only as a reference, and spatial outside/free bending dimensions remain PENDING. Acute spatial bends, full clause8.5/Table4 dimensioning, tolerance adjustment, fabrication feasibility and BS/ACI/engineering release remain outstanding. No numeric policy, cut or mass formula changed. Append-only XLSX fields Z–AC store isometric status, virtual lengths, tangent coordinates and pending dimension status; legacy A–Y indices remain stable.

Edition verification on 2026-10-11: BSI identifies [BS8666:2000 as withdrawn on 1 January 2006](https://knowledge.bsigroup.com/products/specification-for-scheduling-dimensioning-bending-and-cutting-of-steel-reinforcement-for-concrete-1); its [official undated catalogue identifies BS8666:2020 as the current release](https://landingpage.bsigroup.com/LandingPage/Undated?UPI=000000000030045759). ## v0.13 proposed dimension reference workflow

Supplied clauses8.5/8.6/8.8, physical p14/printed p10, were visually inspected again. The new optional measurements-v7 captures explicit XYZ measurement endpoints and their source, with absolute member-axis or straight3D lengths. It distinguishes reference-only values from proposed outside dimensions, always UNVERIFIED, and brackets one user-proposed free dimension without adding tolerance allowances. This enables review against a project drawing; it does not fulfill/approve the remaining BS8.5 fabrication dimension method.
