# รุ่นข้อมูลที่แสดงและส่งออก BOQ — v0.79

ระบบอ่านสมาชิกและไฟล์อ้างอิงครบทุกหน้าจากฐานข้อมูลก่อนประกาศว่าข้อมูลโครงการพร้อม ตารางแสดงครั้งละ50แถว แต่ TOTAL รวมสมาชิกและตำแหน่งทั้งหมดในขอบเขตที่เลือก ไม่ใช่ผลรวมเฉพาะหน้าที่เปิดอยู่ Zone/ชั้นตัดจำนวนตาม occurrenceและคูณค่าต่อสมาชิกครั้งเดียว

ระหว่างโหลดรุ่นใหม่ หน้าจอเก็บ Project/Specที่จับไว้พร้อมสมาชิกชุดเดิมเพื่อแสดงปริมาณชุดเดียวกัน ไม่คำนวณสมาชิกเก่าด้วย Specใหม่ ปุ่มในพื้นที่ทำงานยังหยุดให้รออ่านข้อมูลครบตามขั้นตอนเดิม สิทธิ์ผู้ใช้ สถานะRestore/เปลี่ยนSpecและตัวติดตามประวัติยังใช้ข้อมูลโครงการปัจจุบัน การสลับโครงการไม่เผยแพร่ผลตอบกลับเก่าทับโครงการใหม่

ปุ่ม PDF/Excelใน BOQ Summaryส่งรุ่นของชุดที่ผู้ใช้เห็นไปยืนยันก่อนสร้างSnapshot หากข้อมูลเปลี่ยนก่อนเริ่มจะปฏิเสธโดยไม่บันทึกงาน ต้องโหลดและตรวจยอดใหม่ ถ้าข้อมูลเปลี่ยนระหว่างเตรียม/อัปโหลดกับการบันทึกงาน คำสั่งเดิมตรวจรุ่นและหยุดบันทึกอยู่แล้ว อาจเหลือSnapshotที่ไม่มีงานอ้างถึง;รอบนี้ไม่ได้เพิ่มระบบเก็บกวาด

การจำลองอ่านค้างใช้hookและการคำนวณจริงกับแหล่งข้อมูลควบคุมที่ระบุ COMPONENT QA ONLY ข้อมูล57สมาชิกแสดงคอนกรีต285m³และน้ำหนักที่คำนวณด้วยSpecเดิม7850kg/m³จนอ่านชุดใหม่ครบ จากนั้นจึงเปลี่ยนเป็นSpec8000kg/m³ ผลตอบกลับที่มาช้าหลังสลับโครงการถูกทิ้ง การทดสอบนี้ไม่ใช่หลักฐานเขียนฐานข้อมูลหรือรับรองค่าความหนาแน่น

การตรวจคำสั่งใช้record/transaction doublesเพิ่มเติม ครอบคลุมรุ่นที่ล้าสมัย การจับWorkingSnapshotตามรุ่น และการเปลี่ยนProjectหลังอัปโหลดก่อนcommit ส่วนหลักฐาน localFirebaseจริงและไฟล์ที่ตรวจอยู่ใน [รายงาน](../output/boq-basis-verification/DEVELOPMENT_REPORT.html)

ยังไม่ใช่การตรวจรับโครงการจริงหรือกฎวิศวกรรม/ราคา/owner/Issued/Production ไม่เปลี่ยนสูตรปริมาณหรือทำให้BBSที่ยังไม่กรอกเป็นศูนย์ที่รับรองแล้ว Rules/Auth/config/.envยังอยู่ในการจัดการของผู้ใช้ ไม่มีการdeployในรอบนี้
