# ทำสำเนาสมาชิก — v0.42

เปิดสมาชิกที่บันทึกแล้วในฐานราก คาน เสา พื้น ผนัง หรือองค์ประกอบอื่น แล้วกด **ทำสำเนา** ผู้ใช้ต้องมีสิทธิ์เพิ่มสมาชิกในโครงการปลายทาง ถ้ายังมีการแก้ไขค้างอยู่ ให้บันทึกหรือย้อนการแก้ไขก่อน

เลือกโครงการปลายทางจากโครงการที่มีสิทธิ์ กรอก Member no. ใหม่ และระบุจำนวนเต็มบวกพร้อม Zone / Floor / Grid ของตำแหน่งใหม่ เพิ่มได้หลายตำแหน่ง จำนวนเริ่มว่างเพื่อไม่ใช้จำนวนจากต้นแบบโดยไม่ตั้งใจ ตัวอย่างแสดงจำนวน คอนกรีต แบบหล่อ และน้ำหนักเหล็กตาม **Spec ปลายทาง** แล้วจึงกด **สร้างสมาชิกจากต้นแบบ** ระบบเปิดโครงการและสมาชิกใหม่ให้ทำงานต่อ

## ข้อมูลที่ใช้เป็นต้นแบบ

มิติ ผิวแบบหล่อ งานดิน/Lean/Pedestal รายการหัก ชิ้นส่วนและช่องเปิด พารามิเตอร์คานหลายช่วง พื้นที่อ้างอิงรอยต่อ/ช่องเปิด และข้อมูลเหล็กทุกฟิลด์ที่ schema ปัจจุบันรองรับ ใช้ค่าที่ผู้ใช้กรอกเดิม รวมทั้ง Mark จำนวนต่อชิ้น พิกัด โค้ง เกลียว รัศมี มิติอ้างอิง และความยาวตัดที่ระบุเอง ไม่มีการตีความแบบหรือสร้างแนวเหล็กเพิ่มเติม

สร้างรหัสสมาชิก เหล็ก ตำแหน่ง ชิ้นส่วน ช่วงคาน และพื้นที่อ้างอิงใหม่ พร้อมเชื่อม targetSolidId และรหัสช่วงคานกับชิ้นส่วนใหม่ มิติแบบ implicit main/pedestal ยังคงรหัสตามความหมายเดิม สมาชิกใหม่เริ่ม Draft/version1 พร้อมที่มาต้นแบบและรุ่นที่บันทึก ณ เวลาทำสำเนา ข้อมูลต้นทางไม่เปลี่ยน

## ข้อมูลที่ต้องตรวจใหม่

ไฟล์แบบ จุดชี้ Mark ตารางเทียบ BBS จากไฟล์ต้นทาง ผลดึงข้อมูลจากแบบ ผลตรวจชิ้นเหล็กจริง สถานะตรวจ และการยืนยันตำแหน่ง/มิติ BS ไม่โอนตามต้นแบบ ตั้งเลขแบบ BBS และตาราง A4 ใหม่ รวมทั้งแนบแบบและตรวจจุดชี้ก่อนส่งงาน ไม่คัดลอกสต็อก แผนจอง เศษเหล็ก Revision หรือประวัติส่งออก

Spec ของโครงการต้นทางไม่ถูกคัดลอกไปทับ Spec ปลายทาง ความหนาแน่น/การปัดความยาวและกฎที่รองรับจะใช้ของปลายทาง แต่ค่าที่กรอกเอง เช่น manual cut override ยังคงเป็นข้อมูลที่ต้องตรวจ การทำสำเนาไม่รับรองความสอดคล้องกับ BS/ACI หรืออนุมัติก่อสร้าง

## ข้อมูลเปลี่ยนหรือไม่ได้รับผลสำเร็จ

ตัวอย่างอ้างอิงรุ่นของสมาชิกและทั้งสองโครงการ ข้อมูลเปลี่ยนจะหยุดการสร้าง ให้กด **โหลดต้นแบบและปลายทางใหม่** ข้อมูล Member no. และตำแหน่งที่กรอกยังคงอยู่ การเปลี่ยน Spec/Restore ที่ยังทำงานอยู่จะหยุดการทำสำเนาด้วย

การบันทึกใช้ transaction และ operation ID ป้องกันการสร้างซ้ำ คำขอที่สำเร็จแล้วลองซ้ำด้วยข้อมูลเดิมจะคืนผลเดิม แม้ต้นทางเปลี่ยนภายหลัง หากยังไม่ได้รับผลสำเร็จ ปุ่ม **ลองคำขอเดิมอีกครั้ง** ใช้คำขอเดิมในหน้าต่างปัจจุบัน หรือเลือกกลับไปแก้ข้อมูล การปิด/รีเฟรชหน้าต่างไม่เก็บคำขอค้างนี้ ให้ตรวจสมาชิกปลายทางก่อนลองใหม่ เลขสมาชิกซ้ำและรหัสที่มีอยู่ไม่ถูกเขียนทับ

## ขอบเขตตรวจในรุ่นนี้

640 unit tests ผ่าน รวมการเก็บข้อมูลหกประเภท โค้ง/เกลียวและมิติสามมิติ การเชื่อมรหัส และการล้างหลักฐานเฉพาะสมาชิก มี28เส้นทาง SDK/หน้าจอจริงบน backend ทดสอบแยก ตรวจการทำสำเนาใน/ข้ามโครงการ Spec ปลายทาง การแข่งขันบันทึก สิทธิ์ Viewer/โครงการส่วนตัว หน้าจอ390px ข้อมูลถาวรหลังเปิดใหม่ และ3Dของคานที่ทำสำเนา

ไฟล์จากรุ่น build จริง1 XLSX และ2 PDF (A3/A1) ตรวจปริมาณ ขนาดกระดาษ และ bytes/SHA256 เทียบ Storage/job ที่เสร็จแล้ว ตรวจสูตร Excel ด้วย read-only import/recalculation และ render11แท็บ เครื่องมือ render ต้องปรับช่อง shared string ว่างเฉพาะในหน่วยความจำ และยังแสดงข้อความ Code00 เป็น0 แม้ตรวจ XML ของไฟล์จริงว่าเป็นข้อความ00 ไฟล์จริงและสูตรไม่ถูกเปลี่ยนจากการตรวจนี้ Native Excel print ยังไม่ตรวจรับ

ใช้ Auth/Firestore/Storage จริงเฉพาะในเครื่อง ด้วย Rules เนื้อหาเดิม และตัวช่วย transport framing ของ Storage test runtime จากงานv0.41 ไม่ใช่การกู้คืนทั้งฐานข้อมูล ไม่ใช่ผลทดสอบ production หรือกฎของโครงการจริง ผู้ใช้เป็นผู้จัดการ Rules/deploy เอง ไม่มีการแก้ Rules/.env/Auth configuration หรือ deploy
