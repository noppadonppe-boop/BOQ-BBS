# Read-only engineering comparison — v0.58

v0.59 adds [human Excel/PDF exports from the same captured result](ENGINEERING_REPORT_EXPORTS.md). All formats share one immutable capture/time/digest; the numerical/source/permission boundaries below remain unchanged. Original v0.58 evidence remains historical.

Open a portable preparation file in **กรณีตรวจคำนวณ**, then choose **เทียบค่าจากไฟล์**. The comparison uses its captured member and numerical Spec, reads and verifies the actual permitted reference bytes, and displays independently entered expectations against the existing engine. It does not write a case/run or member, approve engineering, enable fixture persistence, change Rules, or unlock Issued.

The three overall states are **ยังตรวจไม่ครบ** (Pending), **มีผลต่างที่ต้องทบทวน** (Review), and **เทียบครบตามค่าที่กรอก** (Compared). Compared means only that complete entered expectations and diagnostics agree within the user-entered numerical bounds and the captured context/reference checks passed. It is not BS/ACI, fabrication, owner or construction approval. Expected values are never filled from the tested engine. Bounds are not accepted production tolerances.

Each BOQ and per-Mark comparison shows expected, calculated, difference, bound and its own state. A blank expectation or bound remains missing, distinct from an entered zero. Piece counts compare exactly. Out-of-domain entries cannot conclude completeness. Unentered/source-pending reinforcement is unavailable in the total steel row, rather than being accepted as zero; a plain-concrete zero needs the existing explicit no-rebar declaration. Existing general-source/spec changes invalidate that declaration and require explicit renewed input.

Positive cases need all7 totals and every actual Mark's cut/count/mass. Negative cases need1–50 explicit expected diagnostic lines (max300 characters each) covering every actual diagnostic. Incomplete, stale or reference-free cases stay Pending even if some rows match. Missing labels/reference scope also remain incomplete. If a live input/Spec/reference changes, the prior result clears. A change during an asynchronous reference read rejects the late result; compare again against an appropriate capture.

Source verification checks same project, current metadata/ownership/revision/SHA/page count, project-local Storage path, size and actual hash/document pages. Superseded, unreadable, unauthorized, corrupt or oversized files remain Pending. Reference reads are bounded to50MiB; unchanged Firebase Rules enforce access. A foreign project file can be read as a local handoff document but its source-comparison action is disabled. Assigned Viewer can perform this read-only comparison for permitted source bytes and download its report; editing/new-case continuation remain disabled. Account switching clears prior previews/results.

**ดาวน์โหลดรายงานเทียบ JSON** produces a distinct diagnostic format with full captured preparation, comparisons, source-verification time/hash/byte count/pages, context problems, decision and checksum. It contains no source bytes or approval. Reports are bounded to2,000,000 UTF-8 bytes, are not stored in project history and cannot be reopened as an editable preparation file. Preserve the preparation JSON and original document separately. There is no new PDF/XLSX or whole-project Backup/Restore workflow in this increment.
