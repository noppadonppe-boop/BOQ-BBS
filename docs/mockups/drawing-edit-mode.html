โหมดแก้ไขแบบ (Drawing Edit) แบบ Tekla สำหรับแผ่น BBS

ต้นแบบหน้าจอที่ลองใช้งานได้จริง: เปิดแผ่น BBS ของ F1 แล้วเพิ่ม Dimension, Leader / Mark, ข้อความ, ระดับ, รูปตัดใหม่ และ Detail บนแผ่นเดิม ของที่ผู้ใช้เพิ่มเป็นสีส้ม ของที่ระบบสร้างอัตโนมัติเป็นสีเทา ทุกชิ้นยึดกับจุดในโมเดล จึงขยับตามเมื่อโมเดลเปลี่ยน

ลอง: กด D แล้วคลิกมุมฐาน 2 จุด → คลิกที่ว่างเพื่อวางเส้นM คลิกเหล็ก → ป้าย Mark อัตโนมัติS ลากแนวตัดบน PLANเปลี่ยนขนาดฐานที่ “ทดลองแก้โมเดล” ดูของที่ขยับตามคลิกขวาที่วัตถุ

01 · แนวคิดหลักแบบอัตโนมัติ + ชั้นแก้ไขของผู้ใช้ที่ยึดกับโมเดล

แบบ BBS ทุกวันนี้สร้างใหม่ทั้งแผ่นจากโมเดลทุกครั้ง ถ้าให้ผู้ใช้วาดทับลงบนแผ่นตรง ๆ ทุกอย่างจะหายหรือเคลื่อนผิดที่เมื่อเหล็กหรือขนาดเปลี่ยน แนวทางแบบ Tekla คือแยกเป็นชั้น: ระบบยังสร้างแบบอัตโนมัติเหมือนเดิม แล้วนำ “ชั้นแก้ไข” ที่เก็บแยกต่อ member มาซ้อนทุกครั้งที่วาด วัตถุในชั้นนี้เก็บเป็น จุดยึดในโมเดล (มุมคอนกรีต, เหล็ก Mark ไหน เส้นแรก / เส้นสุดท้าย) ไม่ใช่พิกัดบนกระดาษ

โมเดล

member, shapeModel, bars, drawingViews

แบบอัตโนมัติ

buildView / renderView สร้างใหม่ทุกครั้ง ทุก dim / Mark มี id คงที่

ชั้นแก้ไข (ใหม่)

member.drawingEdits: ของที่เพิ่ม + การแก้ของ Auto (ซ่อน / ย้าย / แก้ข้อความ)

ผลลัพธ์

Prim ชุดเดียว → SVG, PDF, DXF (DIMENSION / LEADER / MTEXT) และ Label QA

03 · เมื่อโมเดลเปลี่ยนกฎการยึดจุด

ชนิดจุดยึดตัวอย่างเมื่อโมเดลเปลี่ยน
มุม / กึ่งกลางคอนกรีตมุมฐาน, มุมตอม่อขยับตามจุดนั้น ระยะเส้น dim คงเป็น mm กระดาษ
เหล็กแบบมีความหมายF1/02 เส้นแรก / เส้นสุดท้าย / ตำแหน่ง t บนเส้นตามเส้นเดิมแม้จำนวนเหล็กเปลี่ยน (Snap ที่เส้นริมเก็บเป็น first / last ให้เอง)
เหล็กตามลำดับF1/01 เส้นที่ 9ถ้าเส้นนั้นไม่มีแล้ว → หลุดจุดยึด แสดงสีแดงที่ตำแหน่งเดิม ผู้ใช้ต้องยึดใหม่หรือลบ
จุดอิสระข้อความหมายเหตุอยู่ที่ตำแหน่งเดิมในรูป (พิกัดในรูป ไม่ใช่บนแผ่น จึงย้ายตามกรอบรูป)

เมื่อโมเดลเปลี่ยน แผ่นยังเปิดได้ทันที แต่ป้ายสถานะเป็นสีเหลือง / แดง จนกว่าผู้ใช้กด “ตรวจแล้ว” — ใช้ร่วมกับ Label QA เดิมเพื่อหาป้ายที่ทับกันหลังขยับ

04 · ข้อมูลโครงสร้างที่เสนอ

member.drawingEdits = {
  version: 1,
  objects: [                                  // ≤ 300 ต่อ member
    { id, view: 'plan' | 'sec:<id>' | 'det:<id>', kind: 'dim',
      pts: Anchor[],  dir: 'h' | 'v' | 'aligned',  off: 9,      // off = mm บนกระดาษ จากจุดแรก
      text?: '<> (TYP.)',  style?: { arrow: 'tick' | 'closed' | 'dot', size } },
    { id, view, kind: 'leader', at: Anchor, dx, dy, fromMark?: true, text?: string[], arrow },
    { id, view, kind: 'text',   at: Anchor | { u, v }, lines: string[], size },
    { id, view, kind: 'level',  at: Anchor, dx, label: 'T.O.F.' },
    { id, view, kind: 'cloud',  pts: [u, v][], rev: 'A' },
  ],
  overrides: {                                // แก้ของ Auto ตาม id คงที่จาก renderView
    'dim:overall-x@plan':      { hidden: true },
    'mark:F1/01@sec:def-x':    { dx: -12, dy: 18, text: ['F1/01 (TYP.)'] },
  },
}
Anchor = { k: 'concrete', part, corner: 'x0y0z1' | edge-mid … }
       | { k: 'bar', mark: 'F1/02', pick: 'first' | 'last' | number, t: 0..1 }
       | { k: 'free', u, v }                  // mm ของโมเดลในแกนของรูป
// Detail = drawingViews v2 kind 'detail' { center: Anchor, r, n }  → ViewKey 'det:<id>'

05 · ต่อกับของเดิมจุดที่ต้องแก้ในโค้ด

  • renderView() ต้องให้ dim chain / Mark leader / ระดับ มี id คงที่ (เช่น dim:overall-x, mark:<Mark>) — งานแรกและสำคัญที่สุด เพราะ override ทั้งหมดอ้าง id นี้
  • ฟังก์ชันใหม่ applyDrawingEdits(prims, frame, edits) หลัง renderView(): ใช้ override แล้วแปลงวัตถุผู้ใช้เป็น DimPrim / LeaderPrim / MtextPrim พร้อม draw → SVG / PDF / DXF ได้ทันทีโดยไม่ต้องแก้ renderer
  • ไม่มี drawingEdits = แบบเหมือนเดิมทุก pixel → snapshot tests/sheetSnapshot.test.ts ไม่เปลี่ยน
  • UI = โหมดที่สองใน SheetComposer.tsx (ใช้ canvas, แผ่น, undo และเครื่องมือรูปตัดชุดเดียวกัน) แยก component DrawingEditLayer.tsx
  • รูปแบบตัวอักษร / หัวลูกศร / layer อ่านจาก spec.cadStandard; labelReport() ตรวจรวมของผู้ใช้ด้วย
  • คู่มือ: เพิ่ม topic “แก้ไขแบบ” ใน helpContent.ts + HelpButton ตามกฎ AGENTS.md

06 · ลำดับงานแบ่งเป็น 4 ช่วง

P1แก้ของ Auto + ข้อความ

  • id คงที่ใน renderView
  • ซ่อน / ย้าย / แก้ข้อความ dim และ Mark
  • ข้อความ, Leader ข้อความ, undo / redo, บันทึก
  • schema + DXF / PDF ผ่าน prim เดิม

P2Dimension ยึดโมเดล

  • Snap มุม / กึ่งกลาง / เหล็ก ในทุกรูป
  • Dim chain, เพิ่ม / ลบจุด, ระดับ ▽
  • Mark จากเหล็กที่คลิก (fromMark)
  • แสดงหลุดจุดยึด

P3รูปใหม่

  • รวมเครื่องมือรูปตัดของ Composer
  • Detail view วงกลม + มาตราส่วน
  • 3D ISO, รูปตัดหักมุม

P4สถานะแบบและ Revision

  • สถานะ “ตรงกับโมเดล / ต้องตรวจ”
  • Revision cloud + ตาราง Rev ใน title block
  • บันทึกชุด annotation เป็น Template ตามประเภท
  • คัดลอกการแก้ไปยัง member ที่เหมือนกัน

07 · ต้องตัดสินใจก่อนเริ่มคำถาม

แก้แบบแล้ว member ต้องกลับเป็น Draft หรือไม่แนะนำ: ไม่ — แยกสถานะของแบบ (ตรงกับโมเดล / ต้องตรวจ) ยกเว้นการเพิ่มรูปตัด ซึ่งตอนนี้ทำให้เป็น Draft อยู่แล้ว
ใครแก้แบบได้แนะนำ: Admin / QS / Detailer ของโครงการ, คนอื่นเปิดดูได้อย่างเดียว
เปิดจากตรงไหนแนะนำ: โหมดที่สองใน “จัดหน้าแบบ” (Composer) เพื่อใช้แผ่น / undo / รูปตัดชุดเดียวกัน แทนที่จะเป็นหน้าใหม่
กลุ่มคาน / เสาหลายชั้นComposer ยังไม่รองรับ — P1 รองรับเฉพาะ member เดี่ยว หรือให้แก้ได้ต่อหน้าแผ่นแบบไม่ยึดโมเดล?
