# แผนตัดและฐาน BBS ที่ใช้จัดแผน — v0.48

เลือกสมาชิก/ประเภท/Zone/ชั้น แล้วคำนวณข้อเสนอจากความยาว BBS ที่กรอก ระบบเก็บรุ่นโครงการ สเป็ค รุ่นคำนวณ จำนวนสมาชิก รายการชิ้นงาน สต็อก และเอกลักษณ์ไฟล์ตารางต้นทางพร้อม SHA256 ของฐานนี้ไว้กับแผน ข้อเสนอนี้เป็น Draft สำหรับวางแผน ยังไม่ใช่ใบสั่งผลิตหรือการอนุมัติทางวิศวกรรม

สมาชิกที่ไม่มี BBS ยังเป็น “รอ BBS” ตารางจากแบบที่ยังไม่จับคู่ยังรอข้อมูล หากขอบเขตไม่มีเหล็กจริง ต้องระบุเหตุผล ระบบจัดข้อเสนอจากรายการที่กรอกเพื่อศึกษาสต็อกได้ แต่จองไม่ได้จนข้อมูลเหล็กครบทุกสมาชิกในขอบเขต และไม่มีชิ้นงานที่ขาด การเลือกเฉพาะพื้นที่ที่กรอกครบทำให้จัดแผนสำหรับพื้นที่นั้นได้

การตรวจฐานและความครบนี้อยู่ในแอปรุ่นใหม่ Rules เดิมที่ทดสอบยังอนุญาตให้แอปรุ่นเก่าจองแผนบางส่วนได้ตามหลักฐานก่อนแก้ จึงไม่ใช่การตรวจรับการบังคับนโยบายบนเซิร์ฟเวอร์/แอปรุ่นเก่าหรือการเขียน Firestore โดยตรง เจ้าของ Rules/API ต้องตรวจนโยบายที่ใช้จริงก่อนใช้งาน Production

ก่อนจอง ตรวจ checksum ของฐาน ความครบของขอบเขต รุ่นปัจจุบัน รายการชิ้นงานทุกชิ้น ผลรวมความยาว และ bytes/SHA ของไฟล์ต้นทางอีกครั้ง ใน transaction ตรวจผู้ใช้/สิทธิ์ รุ่นข้อมูล สถานะแผน ตัวตนและจำนวนพร้อมใช้ของสต็อก การจองและยกเลิกไม่หักจำนวนจริง การยกเลิกใช้ยอดที่จองเดิมได้แม้แก้ BBS ภายหลัง คำขอซ้ำด้วยรหัสเดิมไม่สร้างยอด/ประวัติซ้ำ

แผนเก่าที่ไม่มีฐานนี้คงเป็นประวัติ ให้คำนวณใหม่ก่อนจอง แผนที่กู้คืนจาก Backup คงฐานเดิมและ digest เป็นประวัติ ยกเลิกสถานะจองและตั้งยอดจองสต็อกเป็นศูนย์ ไม่ปรับข้อมูลที่ตรึงไว้ให้กลายเป็นแผนใหม่

Excel แผนตัดมีข้อเสนอ/แพตเทิร์น/ชิ้นงาน พร้อมสมาชิกและสถานะข้อมูลเหล็ก ความต้องการตัด สต็อก และไฟล์ตารางต้นทางที่ใช้จัดแผน ข้อมูลโครงการบนแผนใหม่อ้างฉบับที่เก็บไว้ สูตรรอยตัด C8 และเศษขั้นต่ำ C9 ของแผนเดิมคงตำแหน่งเดิม สูตรและผลที่เก็บไว้ได้รับการตรวจและคำนวณซ้ำในตัวอ่านไฟล์เพื่อ QA ยังไม่ใช่การรับรองการพิมพ์จาก Microsoft Excel

ตารางต้นทางที่ระบุ `allOccurrences` ใช้จำนวนเต็มของสมาชิกในการเทียบ ส่วนปริมาณส่งออก/ตัดใช้เฉพาะตำแหน่งที่เลือก ตัวอย่างสังเคราะห์: สมาชิกเต็ม5 ตำแหน่ง เหล็ก3 ชิ้นต่อตำแหน่ง ตารางต้นทาง15 ชิ้น เมื่อเลือก Zone ที่มี2 ตำแหน่ง จะตัด6 ชิ้น การเทียบต้นทางยังเป็น15 ต่อ15 ชิ้น Excel เก็บตัวคูณที่ใช้เทียบกับจำนวนที่เลือกแยกกัน และ PDF แสดงทั้งสองจำนวน ชุด Frozen ใช้จำนวนจากฉบับที่ตรึงไว้ ชุดข้อมูลเก่าที่ถูกแบ่งพื้นที่และขาดฐานจำนวนเดิมไม่ใช้ข้อมูลปัจจุบันหรือจำนวนที่พิมพ์เพื่อเดาย้อน ให้ดาวน์โหลดไฟล์เดิมหรือเลือกชุดข้อมูลเต็ม

ขอบเขตต่อชุดยังจำกัด100,000 ชิ้น แผนที่เก็บไม่เกิน1,000 เส้นและ700KB พร้อมฐานข้อมูล การจองไม่เกิน160 กลุ่มสต็อก แบ่งแผนใหญ่เป็นชุดที่ตรวจได้ รายชื่อสมาชิกของฐานบนหน้าจอแบ่งหน้า25 รายการ

การตรวจนี้ใช้ Firebase ในเครื่องและ Rules เนื้อหาเดิม การบันทึกตัดจริงบน backend ทดสอบ `demo-boq-v041` ถูก Rules เดิมปฏิเสธ และตรวจว่าข้อมูลทุกส่วนไม่เปลี่ยนค้าง จึงยังไม่มีผลตรวจรับการใช้สต็อกจริง/สร้างเศษจากการผลิต การใช้งาน Production ต้องสอดคล้องกับ Rules ที่เจ้าของระบบจัดการเอง และยังต้องมี Issued/วิศวกรรม/กรณีอ้างอิงที่ตรวจรับแล้ว

ไม่มีการแก้หรือ deploy Rules, `.env`, Firebase configuration หรือ Auth service/context ไม่มี Cloud Functions หรือการปรับสูตร BS/ACI ในงานนี้ นโยบายคำนวณคง `geometry-2.2+bs8666-2000-v7` ตาม BS8666:2000 ที่ผู้ใช้ให้ งานจริง GULF ยังคงเป็นแบบอ้างอิงและรอสร้าง BBS/ตรวจตำแหน่ง ไม่สร้างรูปเหล็กจากความยาวที่พิมพ์และไม่ถือว่าตารางจากแบบเป็นการอนุมัติ
