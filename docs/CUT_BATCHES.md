# จัดชุดตัดจากยอดชิ้นงานที่เหลือ

รุ่น0.75เพิ่มการจัดชุดจากยอดที่ยังไม่จอง/ผลิตในฉบับ Issued รวมถึงยอดที่เหลือภายใน Mark/occurrence เดียวหลังยกเลิกแผนที่ผลิตไปบางส่วน ไม่เปลี่ยน BBS หรือปริมาณ BOQ ฉบับเดิม งานนี้ไม่แก้ Rules, Auth, configuration หรือ deploy

## จัดชุดและทำต่อ

เลือก **Issued Rxxx** ในฐาน BBS แล้วระบุ **จำนวนชิ้นสูงสุดต่อชุด** ตั้งแต่1ถึง100,000ชิ้น จากนั้นเลือกสมาชิก Zone หรือชั้นตามเดิม ระบบหักยอดของแผน Reserved และ Consumed ในฉบับเดียวกัน สำหรับแผน Cancelled ที่มีใบตัดบางเส้น จะหักเฉพาะยอดที่ผลิตแล้ว ส่วน Proposal ที่ยังไม่จองไม่ใช้สิทธิ์ยอดชิ้นงาน

ระบบเลือกตามลำดับตำแหน่ง/Mark ที่ตรึงไว้จนถึงเพดาน แล้วส่งเฉพาะ demand ของชุดนี้ให้ตัวคำนวณตัดเหล็ก ความยาวทุกชิ้นมาจาก frozen cutLength การเลือกชุดไม่เปลี่ยนจำนวนสมาชิก ตำแหน่ง ขนาด geometry หรือคอนกรีต/แบบหล่อ/BOQ เดิม จำนวนสมาชิกในฐานแผนยังเป็นขอบเขต BBS ส่วนจำนวนชิ้นใน Captured Demand/Cut Allocation เป็นงานของชุดนี้

เช่น BBS ตำแหน่งเดียวมี10ชิ้น ผลิตแล้ว5ชิ้นและยกเลิกส่วนที่เหลือ ชุดใหม่เลือกได้อีก5ชิ้นในตำแหน่งเดิม โดยไม่แก้จำนวนเหล็กใน BBS หากมีอีกแผนจองระหว่างจัดข้อเสนอ ตอนจองระบบตรวจยอดอีกครั้งและปฏิเสธยอดเกินฉบับ

ขอบเขตต้นทางใหญ่กว่า100,000ชิ้นเก็บเป็นจำนวนได้ แต่แต่ละชุดที่ส่งเข้า solver ไม่เกิน100,000ชิ้น/100,000ตำแหน่ง แผนยังจำกัด1,000เส้นวัตถุดิบและ700KB หากเกิน ให้ลดเพดานหรือแบ่งสมาชิก/พื้นที่ ไม่รับรองว่าเลือก subset นี้ทำให้เศษทั้งโครงการต่ำที่สุด ตัวคำนวณเปรียบเทียบแพตเทิร์นสำหรับ demand ที่เลือกตามเป้าหมายเดิม

## การตรวจข้อมูลและประวัติ

ชุดที่บันทึกมี batch.version1/method=unallocated, maxPieces, scopePieces, availableAtPlanning และ selectedPieces พร้อม allocations ตามตำแหน่งและ inputDigest ยอดเมื่อวางแผนเป็นข้อมูล ณ ครั้งนั้น ไม่ใช่ยอดพร้อมจองปัจจุบัน เมื่อจอง/ตัด ระบบตรวจ subset กับฉบับเดิม แล้วตรวจยอดจอง/ผลิตปัจจุบันอีกครั้ง

ประวัติใบตัดของแผนที่ยกเลิกบางส่วนต้องตรงกับ executionState ก่อนใช้คำนวณยอดที่เหลือ ถ้าประวัติหายหรือผิด จะไม่ถือว่ายอดนั้นว่างแล้วจัดชุดซ้ำ ค่า batch/allocations/demand ที่แก้ผิด ยอดนอก occurrence หรือจำนวนเกินฉบับถูกปฏิเสธ คำสั่งวางแผนตรวจ stockEpoch และสถานะฉบับซ้ำก่อน commit

Excel แสดงชิ้นงานในชุด เพดาน ยอดที่ยังไม่จองเมื่อจัดแผน และยอดตามขอบเขตฉบับ พร้อม allocations/demand ที่บันทึกไว้ จำนวนสมาชิกไม่ได้ใช้คูณชิ้นงานในชุดอีกครั้ง ไฟล์แผนไม่ให้การอนุมัติวิศวกรรมใหม่

## สำหรับเจ้าของ Rules หรือ API

batch และ allocations เป็นส่วน immutable ของ cutPlans ต้องบังคับ subset ตามฉบับ ยอดจอง/ผลิตรวมแผนอื่น การคงยอดที่ผลิตแล้วเมื่อยกเลิก UID/บทบาท และ stockEpoch ฝั่งเซิร์ฟเวอร์ ห้ามแก้ basis/patterns/allocations/batch หลังบันทึกเพื่อข้ามยอด การตรวจ client ไม่แทนการบังคับผ่าน SDK/REST ที่เจ้าของนโยบายดูแลเอง ไม่มีการแก้หรือ deploy Rules ในงานนี้

## ผลตรวจและงานค้าง

ทดสอบการหักยอดจอง/ผลิต การจัดส่วนที่เหลือภายใน occurrence เดียว เพดาน ขอบเขต ฐานใหญ่20ล้านชิ้นที่ส่ง solver เพียง1,000ชิ้น ค่า batch/demand ปลอม และ stockEpoch race ผ่าน domain/record/transaction doubles ตรวจ positive command path และ XLSX serialization ของชุดด้วยข้อมูลจำลอง ไม่ใช่การออก Issued จริง

กับ Firebase จำลองจริง ทดสอบ regression การรับ/จอง/ยกเลิก สิทธิ์แยกโครงการ Worker และหน้าจอ build รวมถึงการปฏิเสธ batch ที่ไม่มี Issued หรือใช้ Frozen โดยไม่เปลี่ยนข้อมูล ฟอร์มเพดานผ่าน component QA ไม่มีการเขียนฐานข้อมูล

ยังต้องตรวจ positive batch/reservation/receipt กับนโยบายจริงและกรณีวิศวกรรมที่รับรอง ก่อนใช้ก่อสร้าง ยังไม่รองรับการตัดไม่ครบแพตเทิร์นภายในเส้นเดียว การแก้ความยาว BBS ระหว่างตัด หรือการจัดลำดับชุดให้ optimal ทั้งโครงการ งาน BS/ACI/วัสดุ/ปิดปลาย/GULF/เจ้าของงาน/Production และข้อกำหนดเดิมทั้ง12ข้อยังไม่ครบ
