# แผนตัดจาก BBS ที่ออกฉบับและการรับเศษกลับ

รุ่น 0.73 เพิ่มเส้นทางจัดแผน จอง และบันทึกตัดจากฉบับ Issued โดยใช้ความยาว/จำนวนที่ตรึงไว้ พร้อมกันยอดชิ้นงานซ้ำตามตำแหน่งสมาชิก ผู้ใช้เป็นผู้จัดการ Rules/API และ deploy เอง งานนี้ไม่แก้ Rules, Authentication หรือ configuration

## จัดแผนและจอง

ใน **ตัดเหล็ก & สต็อก** เลือกฐาน BBS เป็น **Working** สำหรับข้อเสนอวางแผน หรือเลือก **Issued Rxxx** สำหรับฉบับที่ยังไม่ถูกแทนที่ จากนั้นเลือกสมาชิก Zone หรือชั้น ตั้งค่ารอยตัดและความยาวเศษที่ต้องเก็บตามวิธีตัดจริง แล้วเลือกเป้าหมายใช้วัตถุดิบน้อยที่สุด ลดเศษทิ้ง หรือใช้เศษเดิมก่อน

แผนจาก Issued ใช้ `cutLength` ในฐานคำนวณของฉบับนั้น จำนวนมาจากจำนวนเหล็กและตำแหน่งสมาชิกในฉบับเดิม ไม่มีการคำนวณเรขาคณิตใหม่ทับความยาวออกฉบับ แผนบันทึก Spec รุ่นคำนวณ เอกสารต้นทาง สต็อกที่ใช้คำนวณ และ checksum ไว้ร่วมกัน การแก้ Working ภายหลังไม่แก้ฐานของแผน Issued

ก่อนจอง ระบบตรวจทะเบียนออกฉบับ เหตุการณ์ การรับรองชุดกฎและไฟล์ต้นทางอีกครั้ง แล้วตรวจยอดชิ้นงานตาม `memberId / occurrenceId / barId` แผนอื่นที่ Reserved หรือ Consumed ในฉบับเดียวกันใช้ยอดนี้แล้ว การจองซ้ำเกินจำนวน BBS ถูกปฏิเสธ ยกเลิกแผนที่ยัง Reserved เพื่อคืนทั้งยอดจองสต็อกและยอดชิ้นงาน แผน Consumed ยกเลิกกลับเป็นยอดพร้อมใช้ไม่ได้

## บันทึกตัด

ปุ่ม **บันทึกตัดตามฉบับ Issued** เปิดแบบฟอร์มเลขงาน/บันทึกการตัด ตำแหน่งเก็บเศษ และการยืนยันตัดครบตามแพตเทิร์นทุกเส้น บันทึกเฉพาะเมื่อทำครบตามแผน หากตัดไม่ครบหรือแพตเทิร์นเปลี่ยน ให้จัดชุดและแผนใหม่ก่อนบันทึก รุ่นนี้ยังไม่รองรับการบันทึกตัดบางส่วนหรือความยาวเศษจริงที่ต่างจากแผน

คำสั่งตัดยอดเส้นวัตถุดิบ ปลดจำนวนที่จอง เปลี่ยนแผนเป็น Consumed สร้างล็อตเศษที่ยาวถึงเกณฑ์เก็บ และเพิ่ม stockLedger ใน transaction เดียว เศษมีขนาด/เกรดตามวัตถุดิบ ที่มา `Cut <planId>` และตำแหน่งที่ผู้บันทึกระบุ รหัสคำขอเดิมคืนผลเดิมโดยไม่ตัดซ้ำ ฉบับที่ถูกแทนที่ระหว่างตรวจหรือมีคำสั่งสต็อกอื่นเปลี่ยนยอดระหว่างตรวจต้องตรวจใหม่

Working ยังใช้วางแผนและจองได้ การตัด Working ถูกปิดในรุ่น production โหมดทดสอบเดิมอาจลองคำสั่งได้ แต่รายการดังกล่าวมี `simulation: true` และยังต้องผ่าน Rules ของฐานจำลอง ไม่เป็นหลักฐานการออกฉบับวิศวกรรม

## สัญญาข้อมูลสำหรับเจ้าของ Rules หรือ API

| รายการ | ข้อมูลและเงื่อนไขที่ต้องบังคับ |
| --- | --- |
| `planCutting` | ผู้ดูแล/QS ของโครงการ สร้าง Proposal ที่มีฐาน BBS, `inputDigest`, patterns, kerf/minOffcut; ถ้าใช้ Issued ต้องมี `issuedReference`, `revisionNumber` และ `allocations` ตรงข้อมูลที่ตรึงไว้ |
| หลักฐานฉบับ | `issuedReference` ระบุ project/revision/digest, issue event, issuer/time, rule-set digest, approval และ engine ตรงทะเบียน immutable; สถานะฉบับยังเป็น Issued |
| `reserveCutting` | อ่านยอดชิ้นงานของแผน Reserved/Consumed ในฉบับเดียวกัน ตรวจไม่เกินความจุตามตำแหน่ง และอ่านยอดสต็อกจริง อัปเดต reserved/version, สถานะแผน, ledger และ `stockEpoch` พร้อมกัน |
| `consumeCutting` | เฉพาะ Reserved จาก Issued ปัจจุบัน ยืนยันตัดครบตามแผน มี `execution.confirmedPlan=true`, note, offcutLocation; บันทึก plan.execution พร้อม recordedBy/At และ ledger.execution/issuedReference พร้อมยอดก่อน–หลังและ outputs |
| `cancelCutting` | เฉพาะ Reserved คืนยอดจองโดยไม่เพิ่ม quantity ยกเลิกได้เมื่อฉบับเก่าถูกแทนที่แล้ว ไม่ต้องให้ฉบับเก่ากลับมามีสิทธิ์ผลิต |
| ประวัติและเศษ | ledger/operation ไม่แก้ทับ สต็อกเศษสร้างจาก remainder ของแพตเทิร์นที่ตรวจยอดความยาวครบ ไม่ใช้ checksum ที่ client ส่งมาเพียงอย่างเดียวเป็นสิทธิ์อนุมัติ |

นโยบายต้องบังคับ UID/บทบาทแยกโครงการ ป้องกันการข้ามคำสั่งผ่าน SDK/REST และบังคับยอดชิ้นงาน/ยอดสต็อกในฝั่งเซิร์ฟเวอร์ การตรวจ client ไม่แทนการบังคับนั้น Rules ปัจจุบันยังปิด Consumed และไม่อนุญาตเพิ่ม execution ในการอัปเดตแผน จึงต้องตรวจชุดนโยบายที่เจ้าของจัดก่อนใช้การตัดจริง ไม่มีการแก้หรือ deploy Rules ในงานนี้

## ผลตรวจและขอบเขตก่อนใช้จริง

ผ่านการทดสอบรับเข้า/replay ใช้เศษเดิม จองพร้อมกัน ยกเลิก ยอดสต็อกตรงประวัติ Working เก่าถูกปฏิเสธเมื่อ BBS เปลี่ยน สิทธิ์ Viewer/โครงการอื่น และการปฏิเสธ Frozen เป็นแหล่งตัด Issued กับ Firebase จำลองจริง การปฏิเสธตัดของ Rules ไม่ทิ้งยอดเปลี่ยนบางส่วน Web Worker จริงใช้ demand ที่ตรึงไว้ และหน้าจอ build ผ่าน desktop/mobile

การโหลดหลักฐาน Issued ใช้ฟังก์ชันตรวจทะเบียนจริงร่วมกับ record doubles ส่วน commit ทางบวกของการตัด Issued/รับเศษ และ retention ของ metadata การตัดเมื่อ Restore ใช้ transaction/domain doubles เท่านั้น ยังไม่พิสูจน์การบันทึก Issued/Consumed กับนโยบายจริง Restore เก็บที่มาเป็นประวัติ โดยไม่คืนสถานะอนุมัติหรือ active issue records

ยังต้องรับรอง BS/ACI วัสดุ รายละเอียดปิดปลาย กรณีอ้างอิงและแบบ GULF ทดสอบ Issued/Consumed และปริมาณจริงกับนโยบายของเจ้าของ รวมถึงการตรวจรับเจ้าของงาน รุ่นนี้ยังไม่ทำให้ครบข้อกำหนด BOQ/BBS ทั้ง 12 ข้อ
