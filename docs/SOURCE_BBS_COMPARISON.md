# ตรวจเทียบ BBS กับตารางและรูปดัดในแบบ — v0.46

ในหน้า Member เปิดแท็บ **ตรวจเทียบ BBS จากแบบ** เลือก PDF/ภาพที่แนบไว้ ระบุหน้าตารางและที่มาที่ถอดข้อมูล แล้วกรอก Mark, ขนาด, เกรด, จำนวน, ยาวตัด และน้ำหนักเมื่อแบบระบุไว้ การอ่านตารางเป็นการกรอกและตรวจโดยผู้ใช้ ไม่มีการอ่านหรือสร้างแนวเหล็กอัตโนมัติจากภาพ ตารางต้องมีอย่างน้อยหนึ่งรายการและรองรับไม่เกิน 300 รายการ

เลือกฐานจำนวนให้ตรงกับต้นทาง: **ต่อ 1 องค์ประกอบ** หรือ **รวมองค์ประกอบของสมาชิกนี้ทั้งหมด** จากนั้นจับคู่แต่ละรายการกับ Mark ของ BBS ที่สร้างในแอป ระบบใช้ ID ของชุดเหล็กในการจับคู่ หากเปลี่ยนชื่อหรือลบชุดเดิมจะมีข้อความให้ตรวจใหม่ การใช้ชื่อเดียวกับชุดที่ถูกลบไม่ได้จับคู่ให้โดยอัตโนมัติ

ผลเทียบแสดง Mark, ขนาด, เกรด, จำนวนและยาวตัดที่ต่างกัน รวมทั้งรายการที่ยังไม่จับคู่ และ BBS ที่ไม่มีรายการต้นทาง น้ำหนักแสดงผลต่างเพื่อทบทวน โดยไม่มีเกณฑ์คลาดเคลื่อนที่รับรอง น้ำหนักที่ไม่ระบุคงเป็นช่องว่าง ผลรวมแถวต้นทางจะแสดงเฉพาะเมื่อกรอกน้ำหนักครบทุกแถว และแยกจากยอดรวมที่พิมพ์ในแบบ

ตารางอ้างอิงผูกกับไฟล์ เลขหน้าและ SHA256 ไม่ใช่ปริมาณ BOQ อีกชุดหนึ่ง การแก้ตารางกลับ Draft และล้างการยืนยันมิติ BS/ตำแหน่งเหล็ก ทั้งหน้าแก้ไขและคำสั่งบันทึกผ่าน SDK ตรวจเงื่อนไขเดียวกัน หากมีตารางอ้างอิง ต้องแก้ช่องที่ไม่ตรงและจับคู่ให้ครบก่อน Checked การตรงตามช่องเทียบยังไม่ยืนยันรูปดัด ตำแหน่งเหล็ก การทบทวนแบบ หรือความถูกต้องทางวิศวกรรม

## เลือกรูปดัดต้นทางของแต่ละ Mark

เมื่อมีตารางต้นทางแล้ว เลือก **Mark สำหรับดูรูป** ในส่วน **รูปดัดต้นทางและรูป BBS** แล้วกด **เลือกรูปดัดต้นทาง** ระบบเปิด PDF/PNG/JPEG ที่แนบไว้ ให้ระบุหน้า ซูม 100–400% และคลิกสองมุมของรูปดัด หรือกรอกซ้าย/บน/กว้าง/สูงเป็นเปอร์เซ็นต์ของหน้าที่เห็น การหมุน PDF และ CropBox รวมอยู่ในมุมมองแล้ว ไม่ต้องกลับพิกัดเอง กรอบต้องอยู่ในหน้าทั้งหมดและมีพื้นที่อย่างน้อย 0.1% ในแต่ละแกน

กด **ใช้รูปต้นทางนี้** แล้ว **บันทึก** สมาชิก รูปแสดงคู่กับแนวเหล็กที่กรอกในแอป ถ้ายังไม่จับคู่หรือไม่ได้สร้างเหล็กจะแสดงข้อความให้กรอกก่อน ไม่มีการสร้างแนวเหล็กจากภาพ ยาวตัดที่ตรงกันจึงยังไม่ยืนยัน crank, มุม, รัศมี, ปลายดัด หรือการติดตั้ง จำนวนจากตารางอ้างอิงไม่เพิ่มเข้า BOQ/แผนตัดอีกครั้ง

หน้ารูปดัดต่างจากหน้าตารางต้นทางได้ แต่ต้องเป็นไฟล์ฉบับเดียวกัน การเปลี่ยนหน้าล้างกรอบเดิมเพื่อให้เลือกใหม่ การซูมคงพิกัดที่เลือกไว้ การแก้หรือลบรูปกลับ Draft และล้างการยืนยันเดิมโดยไม่ลบ BBS เลือกไฟล์ต่าง SHA จะล้างกรอบทุก Mark เพื่อให้ตรวจใหม่ Viewer ดูรูปได้แต่เปลี่ยนกรอบไม่ได้ การเปลี่ยนบัญชีปิดตัวเลือกของบัญชีเดิมและล้างรูปที่เปิดอยู่

ข้อมูลรูปเก็บเฉพาะ SHA256, หน้า และกรอบ 0–1 ของหน้าที่มองเห็น ไม่เก็บภาพซ้ำบนฐานข้อมูล โปรแกรมตรวจขนาด/checksum/จำนวนหน้าของ bytes ต้นฉบับทุกครั้งที่เริ่มอ่านรูป ตารางเดิมรุ่น1 ยังใช้ได้; เมื่อเพิ่มรูปจะใช้รุ่น2 โดยไม่เปลี่ยนนโยบายคำนวณปริมาณ

## ส่งออกและกู้คืน

Excel เพิ่ม `Source BBS Check` และ `Source BBS Notes` เมื่อสมาชิกมีตารางอ้างอิง จำนวน/ยาวตัด/น้ำหนักจริงอ้างสูตรจาก BBS; สถานะผลเทียบเป็นค่าที่บันทึกขณะส่งออก การแก้ Excel ไม่ตรวจอนุมัติใหม่ในแอป ช่องที่ไม่ทราบใช้เซลล์ว่างจริง และความสูงแถวรองรับหมายเหตุยาว

BBS A3/A1 และตารางตัด/ดัด A4 มีแผ่นประกอบอ้างไฟล์ หน้า SHA256 ค่าต้นทาง/ค่าที่คำนวณ และหมายเหตุ เมื่อใช้กรอบชื่อแบบโครงการ แผ่นประกอบรวมอยู่ในทะเบียนและเลขแผ่น ข้อมูลยังเป็น Draft / NOT FOR CONSTRUCTION; แบ่งขอบเขตชุดส่งออกเมื่อจำนวนหน้าเกินขีดจำกัดเดิม 500 หน้า

รุ่น0.46 เพิ่มแท็บ **Source Shape References** ใน Excel เมื่อมีกรอบรูป และเพิ่มหน้า **Original bending shape / REFERENCE ONLY** ต่อรูปใน PDF แสดง Mark ต้นทาง/การจับคู่ BBS, ไฟล์และ Revision, หน้า, กรอบและ SHA256 เต็ม พร้อมภาพจากต้นฉบับ ภาพและตัวตนเป็นค่าที่ captured ขณะส่งออก ไม่ใช่สูตรสร้างเหล็ก รูปต้นทางเป็น NTS; แบบ BBS ที่คำนวณยังเป็นคนละแผ่น การส่งออกทั้งชุดจำกัดรูปต้นทาง300รูป/50ไฟล์/90MiB และภาพที่อ่าน30MiB เพื่อให้แบ่งชุดได้โดยไม่มีการตัดรายการเงียบ

Frozen เก็บตาราง ณ เวลาบันทึกฉบับไว้ การแก้ Working ไม่เขียนทับ Frozen การตรวจ Backup ตรวจการอ้างไฟล์ด้วย; Restore เปลี่ยน ID ไฟล์ให้ตรงกับไฟล์ที่นำเข้า คง SHA256/แถวตาราง และกลับ Draft ตามขั้นตอนกู้คืนเดิม ทั้งแผนกู้คืนและคำสั่ง SDK ตรวจไฟล์หลังเปลี่ยน ID อีกครั้งก่อนเขียน สมาชิกที่อ้างไฟล์ใหม่ไม่ครบหรือ SHA/หน้าไม่ตรงถูกปฏิเสธ ประวัติไฟล์ส่งออกเก็บเป็นหลักฐานเดิม

## ขอบเขตหลักฐาน

ทดสอบในบริการ Firebase จำลองที่แยกไว้ รวมถึงคำสั่ง Checked ที่ปฏิเสธตารางต่างกัน กรณีสังเคราะห์ที่ตรงและทบทวนจุด Mark ครบก่อน Checked สิทธิ์ viewer, Frozen, Excel/PDF จากงานส่งออกจริง และ Backup/Restore ต้นทาง GULF ถอดตารางด้วยมือ 3 Mark พร้อมไฟล์ต้นฉบับ แต่ยังไม่มีแนวเหล็กที่สร้างจากแบบจริง จึงเป็น Unmapped ไม่ใช่ผลรับรอง BBS โครงการจริง

BS 8666:2000 พร้อม Amendments ตามไฟล์ที่ผู้ใช้ให้ยังเป็นมาตรฐานเริ่มต้นขั้นต่ำเดิม สูตรและนโยบายตัวเลข `geometry-2.2+bs8666-2000-v7` ไม่เปลี่ยน งานนี้ไม่เพิ่ม code33/51 หรืออนุมานการปิดปลาย/ตำแหน่งจากรูป Full BS/ACI acceptance, กรณีวิศวกรรมที่รับรอง, BBS จริงส่งเจ้าของงาน, การพิมพ์ใน Excel จริง และ Production ยังต้องตรวจต่อ

รุ่น0.46 ทดสอบ716กรณีใน49ไฟล์ และ33เส้นทางจริงในเครื่อง ทั้งการบันทึก/สิทธิ์ รุ่นพัฒนาและ build, Frozen, ไฟล์ส่งออกและ Restore ไฟล์ Excel จริง2ชุดมีรูปอ้างอิงชุดละ9รูป PDF A3/A1/A4 จริง3ชุดมีชุดละ25หน้า แสดงผลและตรวจครบ75หน้า รูปใน Frozen PDF ตรวจ pixels กับภาพต้นทาง และรูปฝังใน Excel ตรวจ SHA ของ bytes ตรงกัน เปิดอ่าน/คำนวณใหม่/แสดงผล Excel4มุมมองโดยไม่เขียนทับต้นฉบับ ยังไม่ใช่การพิมพ์ด้วย Microsoft Excel จริง

พบและแก้ปัญหา React StrictMode ปิดตัวอ่าน PDF แล้วนำตัวเดิมกลับมาใช้จนหน้าเลือกกรอบว่าง จากนั้นตรวจหน้าจอจริงซ้ำทั้งสองรุ่นครบ9เส้นทางต่อรุ่น Backup ทดสอบสร้างก่อนแก้กรอบใน UI และก่อนส่งออกไฟล์ชุดนี้; เมื่อกู้คืนตรวจไฟล์ Frozen จาก Storage ของโครงการปลายทางเอง และอ่านรูป Working จาก path ที่เปลี่ยน ID แล้ว ไม่มีการอ่านรูปจากโครงการเดิมแทน

ผู้ใช้ดูแล Rules/deploy เอง งานนี้ไม่แก้หรือ deploy Rules, ไม่แก้ `.env`/Auth และไม่เพิ่ม Cloud Functions รายละเอียดล่าสุดอยู่ใน [รายงาน v0.46](../output/source-region-verification/DEVELOPMENT_REPORT.html) และเก็บ [หลักฐาน v0.39](../output/source-schedule-verification/DEVELOPMENT_REPORT.html) ไว้ตามเดิม
