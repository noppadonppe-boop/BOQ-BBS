# Adjacent/future concrete for bar placement — v0.36

All six member categories offer **พื้นที่อ้างอิงเหล็กรอยต่อ**. This declares rectangular concrete from a previous/next pour or adjoining member for checking an explicitly entered protruding bar. It does not infer reinforcement from the attached drawing, design a joint, or approve anchorage/lap lengths. The supplied GULF column sheet motivates this distinction; the synthetic verification bars are not reconstructed GULF bars.

Enter up to six regions using the same XYZ datum as the owned member. Negative origins are supported; finite coordinates and upper boundaries remain within ±200,000 mm. Each region requires its own stable ID, label and user-entered source/revision/page/reason. These notes are stored for review; they are not automatically validated attachment references or engineering approval.

Version2 adds up to four rectangular openings per region, each with its own ID, label, shared XYZ origin/size and required reference. An opening must fit its parent region. Context openings remain excluded even when another context solid overlaps them. Any positive-volume intersection with occupied owned concrete is rejected: define a matching owned geometric void first. A manual quantity deduction does not substitute for a geometric opening. Context never silently removes owned BOQ concrete only from placement checks.

The placement check uses the union of owned concrete and declared context, with owned voids and context openings excluded. Shared internal faces disappear. A region can inherit member cover or explicitly override it (including zero); its value is a user declaration requiring review. For each external/void surface patch, use the greatest cover of concrete owners responsible for that patch. Owned member cover cannot be lowered by an overlapping reference; a distant high-cover region does not replace all covers globally. Actual bar outside radius and existing arc/helix sagitta allowances remain required. A gap is not bridged. This is a geometric check, not proof of construction sequence, development, lap, confinement or load transfer. Curved/nonrectangular reference regions remain unsupported.

BOQ still uses owned member solids, selected formwork faces, openings, manual deductions, excavation/lean settings and occurrences. Context adds no concrete, formwork, excavation or backfill quantity. It is not a target solid and does not extend a parameterized bar. Actual explicit bar coordinates, cut lengths, diameter mass and selected occurrence multiplication remain unchanged. Changes/removal return the member to Draft and clear both placement and outside-dimension confirmations, including direct SDK saves. A context removal that leaves bars outside owned concrete must be repaired before Save.

Plan/section and 3D show context as dashed gold outlines and context openings in dashed copper/red; owned concrete remains the member mesh. Projected context openings can overlay an owned plan: they are reference outlines at their declared Z, not owned quantity deductions. Negative/beyond-member coordinates affect view framing only. A3/A1 details include a coordinate/cover/reference register. A3 regions with more than one opening use a region sheet followed by registered pairs of openings, keeping maximum500-character references readable and owner page numbering complete. A1 retains one combined sheet per region. A4 schedules include a scope note. Excel includes **Placement Context** and conditional **Context Openings** sheets with exact coordinates, effective cover/basis, references and Marks outside owned concrete. They contain no reference quantity formulas. Existing source drawing export still requires actual current Mark callouts; this increment does not bypass that gate.

Metadata is additive `placementContext` version1 or version2. Existing version1 remains readable exactly; merely opening a member/editor does not migrate it. Applying the current editor explicitly saves version2 and clears both confirmations. Version1 with accidental version2 fields is rejected rather than silently dropping them. There is no automatic regeneration or numerical-engine revision. Existing geometry-2.2/BS2000 v7 quantities and older Frozen records remain pinned. New snapshots/backup/restore include openings and cover declarations. Old Frozen byte preservation and a real local restore are tested, not production recovery.

The actual GULF 2C1-100 reference pilot records only clearly readable 700×700×6600 mm, quantity1 and 3.234 m³. The pilot cover50 mm is an explicitly unconfirmed form placeholder, not a certified interpretation of the drawing offsets. The original PDF is uploaded/downloaded with the same SHA256. Its printed bar data are captured as external reference evidence only; the pilot has no reconstructed reinforcement rows. Rebar0 therefore means **not entered**, not that the actual column has no steel. Source BBS export without Mark callouts is correctly blocked. No original source Issued label authorizes an app release.

Fresh model/schema imports are separated from drawing/engine helpers to avoid an initialization cycle; schema validation and numerical functions are unchanged.
