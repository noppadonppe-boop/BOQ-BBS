# ที่มาข้อมูลปริมาณ BOQ — v0.90

สมาชิกที่สร้างจากหน้าจอเริ่มด้วย **รอยืนยัน** เพราะมิติเริ่มต้นเป็นค่าชั่วคราว เปิด **ที่มาข้อมูลปริมาณ BOQ** ระบุแบบ/วิธีวัด/ขอบเขต ตรวจมิติ รูปทรง ผิวแบบหล่อ รายการหัก งานดิน Lean และจำนวนปัจจุบัน แล้วกดยืนยันและบันทึกสมาชิก

การยืนยันนี้เป็นคำระบุ input ของผู้ถอดปริมาณ ไม่ใช่การอนุมัติวิศวกรรมหรือเจ้าของงาน BBS มาตรฐานและตำแหน่งเหล็กยังต้องตรวจตามขั้นตอนเดิม

เมื่อสถานะชั่วคราว:

- หน้าสมาชิก/BOQ แสดงยอดพร้อมเป็นรอยืนยัน และแยกค่าคำนวณชั่วคราวไว้ดูประกอบ
- Excel BOQ, BOQ Summary และ BOQ Print เว้นช่องคอนกรีต แบบหล่อ ขุด ถม และ Lean ที่ยังไม่พร้อม รวมถึงยอด TOTAL ที่ยังมีสมาชิกค้าง ไม่ใส่สูตรที่เปลี่ยนช่องว่างเป็น0
- แผ่น Quantity Basis เก็บสถานะ ที่มา และตัวเลข preview เดิม งานดินในภาคผนวกระบุ RAW PREVIEW
- PDF BOQ แสดง PENDING และแนบที่มาข้อมูล
- ราคารวมสมบูรณ์ยัง Pending แม้กรอกอัตราครบ ยอดคำนวณจากอัตราที่กรอกยังดูประกอบได้
- คำสั่งตรวจสมาชิกและตรวจเตรียม Issued ของแอปไม่ยอมให้สถานะชั่วคราวผ่าน

แก้มิติ ผิวแบบหล่อ รูปทรง Pedestal รายการหัก ขุด/Lean หรือจำนวนแล้ว คำยืนยันเดิมกลับรอยืนยัน เก็บที่มาไว้ให้ทบทวน การเปลี่ยนชื่อ Zone/Floor/Grid อย่างเดียวไม่เปลี่ยนฐานรูปทรง งานเปลี่ยน General Spec/รับแบบที่กระทบสมาชิกให้ทบทวนอีกครั้ง สำเนาและ Restore ต้องยืนยัน input ปลายทางใหม่ ส่วนย้อนคืนงานแบบบางส่วนคืนข้อมูลที่จับไว้เดิมได้ครบ

ข้อมูลเก่า/Frozen ที่ไม่มี quantityBasis คงฐานรายงานเดิม โดยระบุ Legacy / ยังไม่บันทึกที่มา ไม่มีการย้ายหรือเปลี่ยนค่าประวัติอัตโนมัติ สมาชิกที่มีฐานใหม่นี้แล้วไม่ลบสถานะทิ้งเพื่อย้อนเป็น Legacy ผ่านคำสั่ง saveMember

สถานะนี้เป็นข้อมูล optional version1 ในสมาชิก สูตรปริมาณดิบและรหัส numeric engine เดิมไม่เปลี่ยน การคุมสิทธิ์และการบังคับสถานะใน API/Rules ของเจ้าของยังต้องตรวจ Production แยกต่างหาก ไม่ใช่การเพิ่มข้อบังคับใน Rules ขณะใช้ข้อมูลนี้ต้องใช้แอปรุ่นปัจจุบันร่วมกัน: รุ่นเก่า/API ที่ตัด field ใหม่นี้ทิ้งอาจทำให้ความหมายของรายงานต่างกัน ยังไม่ได้รับรองการเขียนข้ามรุ่น

หลักฐานใช้ Foundation/Cube สังเคราะห์เพื่อทดสอบซอฟต์แวร์: [รายงาน v0.90](../output/quantity-basis-verification/DEVELOPMENT_REPORT.html) ไม่ใช่ปริมาณโครงการจริงที่ตรวจรับแล้ว
