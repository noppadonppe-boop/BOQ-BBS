# Component quantity input review — v0.101

Quantity input can now be explicitly reviewed by component: element count, concrete, formwork, excavation, backfill, lean and entered BBS steel. The old full-input button remains a v1 review. The new selected-component button writes an opt-in v2 Partial record with references, review tokens and SHA256 fingerprints. Count review records occurrence IDs/quantities, allowing an unchanged selected subset to retain its count review. Component totals additionally require a reviewed selected count; complete steel still requires reinforcement coverage. All original numerical calculations, density/rounding and BS/ACI adapters are unchanged.

The input-review state is not an engineering certificate or signature. Fingerprints detect changed input only, using the documented SHA256 submodule of the pinned [noble-hashes library](https://github.com/paulmillr/noble-hashes#usage). It was added without install scripts. These client/domain checks do not establish server enforcement for authorized raw writes; owner-managed Rules are untouched.

Changes invalidate the relevant review. The simple-box face edit retains count/concrete review while geometry edits invalidate concrete; count changes hold dependent totals. Unchanged occurrence subsets can still be reported. Other complex per-unit fields may conservatively invalidate multiple component reviews. Legacy records and v1 review behavior/report policy remain unchanged; only v2 selects quantity-readiness-3.0. Member KPIs/report/register and grouped BOQ, primary Excel/summary/print and PDF all use per-component readiness. Raw preview values remain available for held items.

Fabrication/release/stock checks retain overall-review requirements: count/concrete-only review remains Provisional to those gates and cannot authorize Issued, fabrication quantities or stock reservation. No physical BBS or material mapping is created. Pricing totals remain conservatively held while any required quantities/steel are incomplete; the existing entered-price preview is not a complete tender or construction cost. Project Spec-change/copy/Restore paths continue resetting input review rather than carrying a new approval into another context.

Actual local QA uses the existing source-derived four C1 types. Count1/47/29/1 and per-element concrete3.234m³ were manually checked as input; formwork/joints/material/BBS/locations remain unresolved. The UI now publishes input-reviewed count78 and concrete252.252m³, while all other complete quantities staynull. Actual face/height/count edit transactions and explicit re-review verify invalidation, then restore original numbers. Old Frozen source data remains exact. Registered Excel/A3PDF from one new Frozen basis are hash-verified, recalculated/read/rendered and show only these two ready input totals. Actual Backup/Restore retains raw count/volume but clears all component reviews in the new project. Compiled desktop/mobile,1685unit cases/122files and TypeScript/build pass.

All original twelve requirements, actual engineering/owner/tender measurement acceptance, positive Issued/Consumed, Production policy/performance/concurrency and the known original QA RPC/capture defect remain open. Current runs use the independent existing local runtime. No Rules/.env/Auth/protected Firebase config edits/deploy, Cloud Functions or Production traffic. Protected9/GULF7 and supplied BS reference remain unchanged; old member/revision/artifact inputs are not migrated.
